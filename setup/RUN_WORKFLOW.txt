LANGGRAPH SCIENTIFIC WORKFLOW: COMMAND SEQUENCE

The LangGraph CLI is the future primary entry point. The characterization and
planner commands later in this file remain available as standalone debugging
commands while their logic is migrated into graph nodes.


QUICK COMMANDS

Set workflow.id and application.path once in config.toml. Then run from
/home/zzhong/agentic_workflow:

  ./agentic start
  ./agentic status
  ./agentic review-template
  ./agentic resume
  ./agentic plan
  ./agentic datasets --dry-run
  ./agentic datasets
  ./agentic benchmark
  ./agentic benchmark --execute
  ./agentic continue

The resume command reads the active workflow ID from config.toml. If a review is
pending, it finds and submits that YAML; otherwise it continues the interrupted
node. Full --workflow-id, --application, and --review-file options remain
available as overrides.


PART 0 - LANGGRAPH MILESTONE 0 REVIEW FOUNDATION


STEP 0.1 - Start a persistent workflow

Run from /home/zzhong/agentic_workflow:

  python3 -m cli.main start \
    --workflow-type foundation \
    --application /path/to/application \
    --workflow-id app_001

This creates runs/app_001, writes an immutable v001 draft, saves a SQLite
checkpoint, writes a YAML review template, and pauses. It does not call a model
or execute the application.


STEP 0.2 - Check status or locate the review file

  python3 -m cli.main status --workflow-id app_001

  python3 -m cli.main review-template --workflow-id app_001


STEP 0.3 - Complete the YAML review

Open the reported review file. Set:

  status: completed
  decision: approve
  reviewer: Your Name

Supported decisions are approve, edit, and reject.

For reject, also fill feedback. The graph creates a new immutable draft version
and pauses again.

For edit, create an edited YAML file under runs/app_001/edits, calculate its
hash, and place both path and hash under edited_artifact:

  python3 -m cli.main hash-file \
    --path runs/app_001/edits/edited-artifact.yaml


STEP 0.4 - Resume from the SQLite checkpoint

  python3 -m cli.main resume \
    --workflow-id app_001 \
    --review-file runs/app_001/reviews/pending/milestone0_review.v001.review.yaml

Resume validates workflow ID, stage, artifact version, artifact SHA-256, review
schema, reviewer, decision, and edited artifact when present. The submitted
review is archived exactly as supplied.


PART 1 - LANGGRAPH CHARACTERIZATION WORKFLOW

Run these commands from /home/zzhong/agentic_workflow after activating venv.
The default workflow type is characterization.


STEP 1.1 - Start code analysis and pause at candidate-input review

  python3 -m cli.main start \
    --application /path/to/application \
    --workflow-id app_001 \
    --config config.toml

Optional application-specific guidance:

  python3 -m cli.main start \
    --application /path/to/application \
    --workflow-id app_001 \
    --config config.toml \
    --context "Focus on the production GPU entry point."

The agent uses read-only local codebase tools, writes
runs/app_001/artifacts/candidate_inputs_review/candidate_inputs.v001.yaml,
creates a YAML review template, checkpoints to SQLite, and pauses. It does not
execute the scientific application.


STEP 1.2 - Review candidate inputs

  python3 -m cli.main status --workflow-id app_001

  python3 -m cli.main review-template --workflow-id app_001

Inspect the candidate-input artifact reported by status. These are the proposed
parameters and shapes for the workload model and eventual experiment sweep.
Pay particular attention to model_input, affects, assumptions, and evidence.

Then edit the reported review YAML. Set status to completed, fill reviewer, and
choose one decision:

  approve  Accept the candidate inputs as written.
  reject   Fill feedback; the agent re-analyzes and creates the next version.
  edit     Create corrected YAML under runs/app_001/edits and provide its path
           and SHA-256 in edited_artifact.

Calculate an edited artifact hash with:

  python3 -m cli.main hash-file \
    --path runs/app_001/edits/candidate-inputs.yaml


STEP 1.3 - Resume and derive the theoretical compute/I/O model

  python3 -m cli.main resume \
    --workflow-id app_001 \
    --review-file runs/app_001/reviews/pending/candidate_inputs_review.v001.review.yaml

After approve or edit, the agent treats the approved inputs as authoritative,
derives execution phases, FLOP expressions, and I/O-byte expressions, writes an
immutable application-characterization artifact, and pauses at the second
review gate.


STEP 1.4 - Review and finish the characterization

Run status again, inspect the reported characterization artifact, and complete
its review YAML:

  python3 -m cli.main status --workflow-id app_001

  python3 -m cli.main resume \
    --workflow-id app_001 \
    --review-file runs/app_001/reviews/pending/characterization_review.v001.review.yaml

Approve ends the characterization workflow. Reject with feedback asks the
agent to derive a new immutable version from the same approved inputs. An edit
decision ingests a validated human-edited artifact as a new version.


STEP 1.5 - Recover a failed non-review node

If an API call or deterministic node fails, inspect the checkpoint:

  python3 -m cli.main status --workflow-id app_001

After correcting the cause, retry from the checkpoint:

  python3 -m cli.main continue --workflow-id app_001

Do not use continue while status says awaiting_review; complete the YAML review
and use resume instead.


PART 2 - LANGGRAPH EXPERIMENT PLANNING

After the characterization workflow is approved, start planning:

  ./agentic plan

The command writes a versioned experiment-plan YAML and deterministic CSV, then
pauses. It does not generate large synthetic data or execute the application.

Inspect the paths reported by:

  ./agentic status

The deterministic measured-run formula is:

  algorithm groups x shared base points x hardware targets x repetitions

Complete the reported planning review YAML with approve, reject, or edit, then:

  ./agentic resume

Reject feedback generates the next immutable plan and CSV versions. Approve
marks the experiment plan ready for dataset preparation.


PART 3 - SYNTHETIC DATASET PREPARATION

Before approving the plan, preview the unique scientific datasets and logical
diffraction storage without writing any data:

  ./agentic datasets --dry-run

After the planning review is approved with `./agentic resume`, generate and
validate the application-compatible HDF5 files:

  ./agentic datasets

The command refuses to generate data from an unapproved plan. It writes data
under `runs/<workflow-id>/datasets/pty-chi/` and publishes an immutable
`artifacts/dataset_preparation/synthetic_dataset_manifest.vNNN.yaml`. A safe
rerun verifies and reuses datasets whose specification and SHA-256 checksums
match. Dataset identity depends on scan count and detector shape; epoch count,
batch size, hardware, and algorithm group reuse the corresponding input data.


PART 4 - BENCHMARK RUNNER

Configure the Python environment used by pty-chi in config.toml. It must import
both torch and ptychi:

  [benchmark]
  python_executable = "/path/to/ptychi/venv/bin/python"

Generate the reviewed 90-row command manifest without running the GPU:

  ./agentic benchmark

Inspect the reported benchmark_run_manifest YAML and benchmark_commands CSV.
The manifest must say execution_ready: true. Complete its review and run:

  ./agentic resume

Approval stops at benchmark_ready; it does not consume compute. Start the
approved benchmark explicitly:

  ./agentic benchmark --execute

The executor writes one directory per run under
`runs/<workflow-id>/benchmark/runs/<run-id>/`. Complete results are reused only
when the command SHA-256 matches. Failed results are recorded and are not
automatically rerun. A failed node can be resumed with `./agentic continue`.


PART 5 - DATA VALIDATION AND RESOURCE MODELING

After benchmark execution, the graph parses timing logs and GPU telemetry,
integrates energy, extracts peak memory, checks missing/failed/duplicate runs,
and pauses at measurement_validation_review.

Inspect the validation YAML and its run_decisions. Use edit when changing which
runs are included or excluded, then:

  ./agentic resume

Approval fits independent models for every hardware/algorithm group and pauses
at resource_model_review. Review the supported domain, coefficients, R2, RMSE,
and assumptions, then run `./agentic resume` again.


PART 6 - GENERIC DATA MAPPING AND SYSTEMFLOW INTEGRATION

After resource-model approval, the SystemFlow Mapping Agent inspects the
approved characterization, model contract, experiment plan, and application
source. It drafts a declarative mapping from every fitted input/group selector
to SystemFlow message fields, message properties, or component parameters, and
maps every fitted target to a message or host output. It then pauses at
systemflow_mapping_review.

Inspect the mapping artifact carefully. If the application has no existing
SystemFlow graph contract, component parameters should normally be used rather
than invented upstream message fields. Approve, edit, or reject it, then:

  ./agentic resume

Mapping approval writes a versioned generic
`workflow_application_resource_model.vNNN.json`, loads it with
`WorkflowApplicationResourceModel`, and runs actual SystemFlow ExecutionGraphs
using `ScientificApplicationModel`. It covers every fitted model group and
planned base point without requiring an XRS/domain-specific adapter, then
pauses at systemflow_integration_review.

Inspect the final integration report and finish with:

  ./agentic resume

Final approval sets workflow_status to complete.


PART A - STANDALONE CHARACTERIZATION DEBUG WORKFLOW

source venv/bin/activate

Run every command from:
  /home/zzhong/agentic_workflow


STEP 1 - Configure the application

Open config.toml and set:

  [application]
  path = "/path/to/application"

After this, confirm that the path points to the application source-code root.


STEP 2 - Generate the first characterization

Run:

  python3 -m agents.characterization.cli

After it finishes, inspect:

  agents/characterization/output/analysis_report.md
  agents/characterization/output/application_characterization.yaml

Do not run STEP 2 again after writing a review because STEP 2 starts a new
first-pass analysis and recreates human_review.yaml.


STEP 3 - Write the human review

Open:

  agents/characterization/output/human_review.yaml

For corrections, set:

  "status": "needs_revision"

Write feedback in additional_context. Structured input_decisions,
formula_decisions, and phase_decisions are optional. Also fill reviewer and
reviewed_at when desired.


STEP 4 - Apply the human review

Run:

  python3 -m agents.characterization.cli \
    --review agents/characterization/output/human_review.yaml

The agent reads the current characterization and human review, checks source
code again when necessary, and updates application_characterization.yaml and
analysis_report.md. It does not overwrite human_review.yaml.

After it finishes, inspect the two updated files again.


STEP 5 - Request another revision if needed

Edit human_review.yaml again. Keep status as needs_revision and replace or
update the feedback so it describes the next requested changes.

Then repeat STEP 4.


STEP 6 - Approve the characterization

When the characterization is correct, edit human_review.yaml and set:

  "status": "approved"

Add reviewer and reviewed_at, then run the same STEP 4 command:

  python3 -m agents.characterization.cli \
    --review agents/characterization/output/human_review.yaml

This records explicit human approval without asking the model to make another
revision. Confirm that analysis_report.md now shows status approved.


PART B - EXPERIMENT PLANNING


STEP 7 - Configure planner limits

Open config.toml and review:

  [planner]
  characterization_path = "agents/characterization/output/application_characterization.yaml"
  output_path = "agents/planner/output"
  max_total_runs = 100
  default_hardware = ["A100"]
  repetitions = 3

The characterization must already have analysis.status and review.status set
to approved. Select only the hardware intended for this experiment.


STEP 8 - Generate the first experiment plan

Run:

  python3 -m agents.planner.cli

Optional planning guidance can be supplied with:

  python3 -m agents.planner.cli \
    --context "Use R from 64 to 4096 and compare A100 with H200."

After it finishes, inspect:

  agents/planner/output/planning_report.md
  agents/planner/output/experiment_plan.yaml
  agents/planner/output/dry_run_matrix.csv

Confirm the variable roles, values, prediction domain, hardware targets,
measurement boundary, repetitions, total run count, validation issues, and
synthetic-input specification.


STEP 9 - Write the planning review

Open:

  agents/planner/output/human_review.yaml

Record requested changes in additional_context or the structured decision
lists. Keep the status awaiting_human_review until the planner review/revision
command is implemented. Do not pass an unapproved plan to the Benchmark Runner.
